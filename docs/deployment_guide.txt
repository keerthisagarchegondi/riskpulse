RiskPulse Production Deployment Guide

Purpose
This guide describes how to provision, configure, deploy, verify, and roll back
RiskPulse services in staging and production. It is written for operators with
AWS, Snowflake, GitHub Actions, Docker, and database access.

Deployment Principles
- Deploy the same container images through staging and production.
- Use immutable image tags, preferably the Git commit SHA.
- Store credentials in AWS Secrets Manager or GitHub environments, never in code.
- Run CI, data quality, ML validation, and security scans before deployment.
- Deploy stateful dependencies before stateless application services.
- Verify health, logs, metrics, and business data after every release.

Production Components
- FastAPI API service: src/api/app.py, port 8000.
- Kafka worker: src/ingestion/kafka_consumer.py.
- Streamlit dashboard: dashboards/streamlit/app.py, port 8501.
- Airflow orchestration: airflow/dags and airflow/plugins.
- PostgreSQL operational database.
- Redis cache and rate-limit backend.
- Kafka raw, validated, enriched, scored, alert, DLQ, metrics, and audit topics.
- Snowflake analytics warehouse.
- S3 data lake and model artifact storage.
- CloudWatch logs, metrics, dashboards, and alarms.
- GitHub Actions CI/CD workflows.

GitHub Environment Protection
Create protected environments named staging and production.

Staging:
- Required reviewers optional.
- Deployment branch: develop.
- Secrets scoped to staging roles and endpoints.

Production:
- Required reviewer approval mandatory.
- Deployment branch: main or manual workflow_dispatch only.
- Secrets scoped to production roles and endpoints.
- Use GitHub OIDC to assume AWS roles. Avoid static AWS access keys.

Branch Protection
main:
- Require pull request before merge.
- Require CI workflow to pass.
- Require conversation resolution.
- Require linear history.
- Restrict direct pushes.
- Require signed commits if organization policy supports it.

develop:
- Require pull request before merge.
- Require CI workflow to pass.
- Require branch to be up to date before merge.
- Require conversation resolution.

Infrastructure Provisioning Order
1. Provision network, private subnets, security groups, and load balancer.
2. Provision S3 buckets and lifecycle/encryption policies from infrastructure/terraform/modules/s3.
3. Provision IAM roles and least-privilege policies from infrastructure/terraform/modules/iam.
4. Provision CloudWatch log groups, dashboards, and alarms from infrastructure/terraform/modules/cloudwatch.
5. Provision PostgreSQL and Redis.
6. Provision Kafka or connect to the managed Kafka cluster.
7. Provision Snowflake databases, schemas, stages, and warehouse roles.
8. Create ECR repositories for api, worker, streamlit, and airflow.
9. Create ECS task definitions and services for api, worker, streamlit, and airflow.
10. Configure GitHub environments, variables, and secrets.

Secrets Management
- Store database passwords, API keys, JWT secrets, Snowflake credentials, and notification tokens in AWS Secrets Manager.
- Enable database password rotation where supported.
- Scope each ECS task role to only the secrets it needs.
- Validate that no credentials are committed:
  git grep -n "password\\|secret\\|api_key" -- ':!docs' ':!tests/fixtures'

Container Build
Development validation:
docker compose -f docker-compose.yml config --quiet
docker compose -f docker-compose.prod.yml config --quiet

Build production images:
docker compose -f docker-compose.prod.yml build api worker streamlit airflow

Makefile equivalent:
make docker-build-prod

Local smoke deployment:
docker compose -f docker-compose.yml up -d
docker compose -f docker-compose.yml ps
docker compose -f docker-compose.yml down

GitHub Actions Flow
Pull request to develop or main:
- Checkout.
- Setup Python.
- Install dependencies.
- Run black, isort, flake8, and mypy.
- Run unit tests with the 90 percent coverage gate.
- Run security regression tests.
- Run data quality validation tests.
- Run ML model validation tests.
- Start Docker integration dependencies.
- Run integration tests.
- Run Bandit and Safety.
- Validate compose files.
- Build Docker images.
- Upload coverage and security artifacts.

Merge to develop:
- Reuse CI.
- Build and push staging images to ECR.
- Deploy staging ECS services.
- Run staging E2E checks.
- Notify team.

Production:
- Manual workflow_dispatch or merge to main.
- Require protected environment approval.
- Capture rollback task definitions.
- Deploy production images.
- Run smoke tests.
- Monitor for five minutes.
- Run rollback automatically on failure.

Manual ECS Deploy
Set environment variables:
AWS_REGION=us-east-1
ECR_REGISTRY=<account>.dkr.ecr.us-east-1.amazonaws.com
ECS_CLUSTER=<cluster-name>
ECS_SERVICE_PREFIX=riskpulse-production
IMAGE_TAG=<immutable-tag>
SERVICES="api worker streamlit airflow"

Dry run:
DRY_RUN=true scripts/deploy.sh production <image-tag>

Deploy:
scripts/deploy.sh production <image-tag>

Rollback Flow
Rollback requires task definition state files, one per service:
- deployment-state/api.taskdef
- deployment-state/worker.taskdef
- deployment-state/streamlit.taskdef
- deployment-state/airflow.taskdef

Dry run:
DRY_RUN=true scripts/rollback.sh production deployment-state

Execute:
scripts/rollback.sh production deployment-state

Post-Deployment Verification
Reusable smoke suite:
python scripts/smoke_test.py --base-url https://api.example.com --streamlit-url https://dashboard.example.com --airflow-url https://airflow.example.com --retries 10 --retry-delay 15 --report-file deployment-reports/smoke-production.json

Production gate runner:
PRODUCTION_BASE_URL=https://api.example.com RUN_AWS_CHECKS=true RUN_TERRAFORM=false scripts/verify_deployment.sh production

API:
- GET /health/live returns status 200.
- GET /health/ready returns ready true and dependencies healthy.
- POST /api/v1/transactions accepts a valid test transaction in staging.

Worker:
- Consumer lag below 10,000 messages.
- DLQ volume stable.
- Processing latency P99 below 5 seconds.

Database:
- New transactions land in PostgreSQL.
- Risk scores join to transactions.
- Fraud alerts join to scored transactions.

Snowflake:
- Raw transaction load succeeds.
- Materialized or reporting views refresh.
- Row-level security filters by tenant or role.

Dashboards:
- Streamlit real-time monitor loads.
- Streamlit model performance and alert management pages render.
- Power BI refresh completes from Snowflake.

Security:
- API rejects missing or invalid credentials.
- Rate limiting returns 429 after threshold breach.
- CloudWatch logs scrub PII.
- Security audit log captures access events.

Rollback Decision Criteria
Roll back immediately when any of these persist for more than five minutes:
- API 5xx error rate greater than 1 percent.
- Pipeline P99 latency greater than 5 seconds.
- Kafka consumer lag greater than 10,000 messages.
- Fraud rate spike greater than 2x baseline without business explanation.
- Health readiness fails for api, worker, or airflow.
- Data quality tests fail against staging after deployment.
- Model validation shows accuracy or fairness regression.

Release Closeout
- Confirm GitHub deployment status is successful.
- Confirm CloudWatch alarms are green.
- Confirm staging or production smoke tests are attached to the run.
- Confirm rollback state is retained for the deployed version.
- Record the release in CHANGELOG.txt.
